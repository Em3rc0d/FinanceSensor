# Security Policy

FinanceSensor handles security-sensitive financial and Gmail integration concepts. The public repository is intentionally designed so that source code, synthetic fixtures, architecture documents and sanitized evidence can be shared without granting access to real financial data or provider authority.

## Hard trust boundary

```text
PUBLIC_REPOSITORY != FINANCESENSOR_TRUSTED_EDGE
GITHUB_HOSTED_CI != FINANCESENSOR_TRUSTED_EDGE
CI_FIXTURES != REAL_FINANCIAL_DATA
```

Real Gmail OAuth authorization, refresh/access tokens, authorization codes, PKCE verifier material, OAuth credential files, real Gmail content and real financial plaintext must remain on the controlled local edge and must never be committed, uploaded as CI artifacts or placed in GitHub Actions secrets for the Level-C proof path.

## Never commit

- `.env` files containing real configuration;
- Google OAuth Desktop credentials JSON;
- OAuth client secrets;
- Gmail access or refresh tokens;
- authorization codes or PKCE verifiers;
- real Gmail message IDs, addresses, subjects, bodies or snippets when they identify a real mailbox/message;
- real financial transaction plaintext;
- private keys, certificates containing private material, signing keys or personal SSH credentials;
- `financesensor-level-c-result.json` generated by real-provider execution.

The root `.gitignore` blocks the common local forms of these files. Ignore rules are defense-in-depth, not permission to store secrets in the repository directory.

## CI policy

Active public CI runs only on ephemeral GitHub-hosted runners. Active workflows must:

- use `ubuntu-latest`;
- declare `permissions: contents: read`;
- contain no `${{ secrets.* }}` references;
- never perform interactive OAuth or real Gmail execution;
- use synthetic fixtures only for financial-content tests.

`tools/validate-ci-runner-policy.mjs` enforces this routing boundary.

## Gmail Level C

The Level-C helper may be packaged in CI, but provider authorization and execution occur only on the controlled local edge. Sanitized evidence may record aggregate status, bounded request counts, byte totals, latency aggregates and pass/fail state. It must not record provider credentials, mailbox identity, message identifiers or financial plaintext.

## OAuth client identifiers

OAuth client IDs are public identifiers, not secrets. An identifier appearing in source must never be treated as authorization. Client secrets, tokens and authorization codes remain confidential regardless of whether the client ID is public.

## Reporting a vulnerability

Do not open a public issue containing credentials, tokens, personal financial information, private Gmail data or exploit material copied from a real account. Use GitHub's private vulnerability reporting mechanism when available for this repository, or contact the repository owner privately through their GitHub profile.

## Disclosure invariant

```text
SANITIZED_EVIDENCE != RAW_PROVIDER_DATA
PUBLIC_CODE != PROVIDER_AUTHORITY
PUBLIC_CLIENT_ID != SECRET
```
